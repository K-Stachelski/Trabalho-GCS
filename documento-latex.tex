\subsection{Equipe}
    \subsubsection{Modelo Prioridade ou Modelo Severidade}
    R: O modelo adotado para o trabalho foi o Modelo de Prioridade, já que as classificações orientavam a saber quanto tempo seria necessário para realização das tarefas. As classificações são: Alta onde a resolução tem que ser imediata, enquanto a Média seria para as tarefas que podem ser feitas depois sem dar erro nas entregas, a de Baixa prioridade seria para apenas quando tivesse tempo disponível. Após resolvidas as Alta e Média prioridades, adotamos a Estratégia Good First, para selecionar tarefas de baixa carga de trabalho.

    \subsubsection{Modelo de Ramificação}
     R: O modelo de ramificação (Branching model) utilizado foi o Feature Branch Workflow combinado com o Developer Branches (Ramificações por Desenvolvedor).
     A escolha desse fluxo se da por isolamento de código, segurança nas alterações e a facilidade no processo de integração ao codigo principal.
     
     \paragraph{Estrutura usada:}
     \begin{itemize}
        \item Main: Que mantem o histórico oficial e estável do software, onde so podera ser alterado se for dado um Merge, pois a revisão e testes foi dado.
        \item Developer Branch: É usado por cada Dev para separar o que cada um fez, alem de ser individual para cada um. Funciona um meio intermediario e validação do que cada Dev fez.
        \item Freature Branch: Serve para ser temporario e de vida curta, criada apenas para a execução de uma tarefa especifica relacionada a uma Issue, usada também para identidicar quem fez e a funcionalidade abordada.
     \end{itemize}

    \paragraph{Motivos:}
    \begin{itemize}
        \item Isolamento de Correções;
        \item Código principal isolada das demais modificações;
        \item Branchs de vida curta;
        \item Facilidade de Rastreamento.
    \end{itemize}
     
    \subsubsection{Padrão Semantico}
     R: Foi adotado durante a realização do trabalho Commits com Mensagens Simples, direto e atômicos, alem de ser de facil entedimento para o restante da equipe.

     \paragraph{Dois tipos de Padrão utilizados:}
     \begin{itemize}
          \item Commits Descritivos Diretos: Mensagens objetivas focadas na ação executada;
          \item Commits Semânticos Padronizados: Mensagens utilizando os prefixos. 
     \end{itemize}
